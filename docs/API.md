# Local HTTP API

`wengine-helper.exe --daemon` serves a JSON API on `http://127.0.0.1:43196` for the Wallpaper Engine
overlay, the installer and local tooling. The protocol is intentionally small and unversioned: the
overlay and the daemon ship in one release, so a request/response change is made on both sides in the
same change.

Behavior, storage and the security rationale are in [ARCHITECTURE.md](ARCHITECTURE.md); this document
is the contract.

## Authentication

Every request except `GET /api/ping` must carry the per-install token:

```http
X-Wengine-Client: <48 lowercase hex characters>
```

The token is generated by the installer into `wengine-token` and embedded into
`scripts/wengine-plus.js`. Requests with a missing or wrong token are answered with
`403 Missing or invalid client token`.

When a browser sends an `Origin` header it must be `null`, `http://wpx.internal` (the Wallpaper
Engine CEF UI), `file://…` or a loopback origin (`localhost`, `127.0.0.1`, `[::1]`, with or without
a port). Any other origin is answered with `403 Forbidden origin` before the token is checked. CORS
allows `GET` and `POST`, the `Content-Type` header and `X-Wengine-Client`.

`GET /api/ping` is deliberately unauthenticated: it is the single-instance probe used before a second
helper starts, and the readiness check the UI runs.

## Conventions

- Request bodies are JSON with `Content-Type: application/json`.
- Query parameters are camel-free snake_case, matching the Rust field names.
- A successful command answers `200` with `{"ok": true, …}`.
- A recoverable failure answers `200` with `{"ok": false, "error": "<message>"}` unless a handler
  documents a different shape.
- Extractors reject bad input before a handler runs: a body without `Content-Type: application/json`
  answers `415`, malformed JSON answers `400`, and a well-formed body missing a required field
  answers `422`. `/api/workshop/item` answers `400` itself when the `id` query is missing.
- An unknown route answers `404`.
- A handler-level failure (Steam unreachable, QR session error) answers `500` with `{"error": …}` or
  an embedded `error` field, as documented per route.
- No response contains the API token, cookies, passwords or file contents.

The overlay calls these routes through `window.WengineHelper`; the mapping is at the end of this
document.

## Service

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/ping` | — | `200 text/plain` `pong` |
| `POST` | `/api/heartbeat` | — | `{ "ok": true }`; arms the 15 s watchdog |
| `POST` | `/api/shutdown` | — | `{ "ok": true }`; the process exits ~200 ms later |
| `GET` | `/api/dialog/folder` | — | `{ "ok": true, "path": "…" }` or `{ "ok": false, "cancelled": true }` |

`/api/dialog/folder` opens the native Win32 folder picker on a blocking thread and is used when the
user chooses an extraction destination.

## Authentication — Steam web session

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/auth/status` | — | `AuthStatus` |
| `POST` | `/api/auth/qr/begin` | — | `QrBegin` or `500 { "error": … }` |
| `POST` | `/api/auth/qr/poll` | `{ "client_id": "…", "request_id": "…" }` | `QrPoll` |
| `POST` | `/api/auth/cookie` | `{ "steamid": "…", "steam_login_secure": "…", "persona_name": "…"? }` | `{ "ok": true, "session": AuthStatus }` or `{ "ok": false, "error": … }` |
| `POST` | `/api/auth/login` | `{ "username": "…", "password": "…" }` | `{ "ok": true, "status": AuthStatus }` or `{ "ok": false, "error": … }` |
| `POST` | `/api/auth/logout` | — | `{ "ok": true }` (removes `steam_session.json`) |
| `POST` | `/api/steam/login/system` | — | `{ "ok": true, "status": AuthStatus }` or `{ "ok": false, "error": … }` |

`GET /api/auth/status` also reports `is_logging_in` while a credentials login is in flight.

The QR flow: `qr/begin` returns `client_id`, `request_id`, the `challenge_url` and an SVG QR code;
the UI renders the SVG and polls `qr/poll` until the status changes. The poll returns
`status: "waiting" | "success" | "error"` with the session on success. `qr/begin` and Steam
credentials login both talk to Steam with a 30-second timeout per request.

## Authentication — download accounts

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/accounts/list` | — | `AccountsData` |
| `POST` | `/api/accounts/select` | `{ "index": 1 }` | `{ "ok": true }` or `{ "ok": false }` |
| `POST` | `/api/accounts/add` | `{ "username": "…", "password": "…"? }` | `{ "ok": true, "account": AccountItem }` |
| `POST` | `/api/accounts/remove` | `{ "username": "…" }` | `{ "ok": true }` or `{ "ok": false }` |
| `POST` | `/api/accounts/qr/start` | — | `{ "ok": true }` or `{ "ok": false, "error": … }` |
| `GET` | `/api/accounts/qr/status` | — | `QrDownloadStatus` |
| `POST` | `/api/accounts/qr/cancel` | — | `{ "ok": true }` |

The `Auto` entry (index 0, `is_auto: true`) always exists and cannot be removed. `add` returns the
new entry without its password. The QR routes drive DepotDownloaderMod's QR login as a child process
and report `status: "idle" | "starting" | "waiting_qr" | "success" | "failed"`, plus `qr_data` (a
block-drawing QR string), `username` and `error`.

## Plugins and the .NET runtime

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/plugins/status` | — | `PluginStatus` |
| `POST` | `/api/plugins/ensure` | — | `{ "ok": true }` (the work continues in the background) |
| `GET` | `/api/dotnet/status` | — | `DotnetStatus` |
| `POST` | `/api/dotnet/ensure` | — | `{ "ok": true }` (background) |

`ensure` is idempotent while a job is running. Progress is read from the status routes by polling;
there is no push channel.

## Metadata

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/metadata/all` | — | Object keyed by pubfile id |
| `POST` | `/api/metadata/save` | `{ "pubfileid": "…", "metadata": { … } }` or `{ "all": { "<id>": { … } } }` | `{ "ok": true }` |
| `POST` | `/api/metadata/delete` | `{ "pubfileid": "…" }` | `{ "ok": true, "removed": true\|false }` |

`metadata` is an opaque JSON object written verbatim; the daemon does not interpret its fields. The
`all` form merges the provided map into the store and is used by the overlay to seed metadata loaded
from a wallpaper folder.

## Updates

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/update/check` | `force=true\|false`, `mock=true\|false` | `UpdateInfo` |
| `GET` | `/api/update/status` | — | `UpdateInfo` |
| `POST` | `/api/update/download` | — | `{ "ok": true }` or `{ "ok": false, "error": … }` |
| `POST` | `/api/update/apply` | — | `{ "ok": true }` or `{ "ok": false, "error": … }` |
| `GET` | `/api/update/mock/release` | — | GitHub-release-shaped JSON serving a zip of the current executable |
| `GET` | `/api/update/mock/binary` | — | A zip archive with the running executable as `application/zip` |

A check is cached for 300 seconds unless `force=true`. Errors are reported inside `UpdateInfo`
(`status: "error"` and an `error` message), not as an HTTP error. A `download` validates the archive
size and SHA-256 against the GitHub API digest before extracting `wengine-helper.exe.update` and
fails while another update operation is in flight. `apply` requires a previously downloaded and
validated `wengine-helper.exe.update`.

The mock routes exist for local end-to-end testing and are guarded like every other route. Point
`WENGINE_UPDATE_URL` at a release-shaped JSON document to test against a different source.
`WENGINE_MOCK_UPDATE=1` makes the automatic check use the mock release.

## Workshop

| Method | Path | Body / query | Response |
|---|---|---|---|
| `GET` | `/api/workshop/browse` | `BrowseQuery` | `WorkshopPage`; `500` with an empty backup page on failure |
| `GET` | `/api/workshop/item` | `id=<pubfile id>` | `WorkshopItem`; `400` without an id; `500` when nothing is cached |
| `POST` | `/api/workshop/download` | `{ "pubfileid": "…" }` | `{ "ok": true, "pubfileid": "…" }` or `{ "ok": false, "error": … }` |
| `GET` | `/api/workshop/download/all` | — | Map of pubfile id → `TaskStatus` |
| `GET` | `/api/workshop/download/status` | `pubfileid=<id>` | `TaskStatus` or `null` |
| `POST` | `/api/workshop/download/cancel` | `{ "pubfileid": "…" }` | `{ "ok": true\|false, "pubfileid": "…" }` |
| `POST` | `/api/workshop/extract` | `{ "pubfileid": "…"?, "file": "…"?, "output_dir": "…"? }` | `{ "ok": true, "pubfileid": "…" }` or `{ "ok": false, "error": … }` |
| `GET` | `/api/workshop/extract/status` | `pubfileid=<id>` | `ExtractStatus` or `null` |
| `POST` | `/api/workshop/delete` | `{ "pubfileid": "…"?, "file": "…"? }` | `{ "ok": true, "deleted": true\|false, "pubfileid": "…" }` or `{ "ok": false, "error": … }` |

`BrowseQuery` fields (all optional except the defaults):

| Field | Type | Default | Meaning |
|---|---|---|---|
| `page` | integer | `1` | One-based page number |
| `sort` | string | `trend` | Wallpaper Engine sort value; mapped to Steam |
| `text` | string | empty | Search text; surrounding quotes mean exact search |
| `required_tags` | string | — | Comma-separated tags that must be present |
| `excluded_tags` | string | — | Comma-separated tags that must be absent |
| `required_flags` | string | — | Comma-separated Steam flags (`incompatible`, …) |
| `incompatible` | boolean | `false` | Adds `requiredflags[]=incompatible` |
| `itemid` | string | — | Author id, vanity name, profile path or full author URL |
| `preset` | string | — | Collection/shared-file id; the Steam URL becomes the shared-file details page |
| `token` | integer | `0` | Opaque pagination token echoed back |
| `num_per_page` / `numperpage` | integer | `50` (`30` for authors) | Page size |

Downloads are per wallpaper and run as child processes; the routes return as soon as the task is
registered, and progress is polled from `/api/workshop/download/all`. Extraction resolves the package
from the wallpaper directory or from the supplied `file`, and writes into the wallpaper directory or
`<output_dir>\<pubfileid>`.

Deletion accepts a wallpaper path (`file`), a pubfile id, or both. A path is accepted only when it is
a direct child of one of the known wallpaper roots and looks like a wallpaper (a `project.json` or
preview file is present, or a pubfile id was supplied). The response reports whether anything was
deleted; a refused path returns `ok: false` with an explanation.

### Failure shape of a browse request

A Steam failure produces HTTP `500` with a page-shaped body so the overlay can render a fallback:

```json
{
  "action": "queryWorkshop",
  "wallpapers": [],
  "pagecount": 1,
  "token": 0,
  "isbackup": true,
  "error": "Steam returned HTTP 429 for https://steamcommunity.com/workshop/browse/?…"
}
```

## Models

### AuthStatus

```json
{
  "logged_in": true,
  "is_logging_in": false,
  "steamid": "76561198000000000",
  "persona_name": "name",
  "avatar_url": "https://…"
}
```

`steamid`, `persona_name` and `avatar_url` are `null` when logged out.

### QrBegin / QrPoll

```json
{ "client_id": "…", "request_id": "…", "challenge_url": "…", "qr_svg": "<svg …>…</svg>" }
```

```json
{
  "status": "waiting",
  "session": null,
  "error": null
}
```

`status` is `waiting`, `success` or `error`; `session` is an `AuthStatus` on success.

### AccountsData / AccountItem

```json
{
  "selected_index": 0,
  "accounts": [
    { "index": 0, "username": "Auto", "is_custom": false, "is_auto": true },
    { "index": 1, "username": "login", "is_custom": true, "is_auto": false }
  ]
}
```

### QrDownloadStatus

```json
{
  "status": "waiting_qr",
  "qr_data": "███…",
  "username": null,
  "error": null
}
```

### PluginStatus

```json
{
  "ready": false,
  "depot_downloader_ready": true,
  "repkg_ready": false,
  "dotnet_ready": true,
  "is_downloading": true,
  "current_plugin": "RePKG",
  "progress": 42.5,
  "message": "Downloading RePKG (12.3 MB / 29.1 MB)...",
  "error": null
}
```

### DotnetStatus

```json
{ "phase": "downloading", "message": "Downloading .NET Runtime 9.0.17 (25.0 MB / 55.2 MB)...", "progress": 45.2 }
```

`phase` is `checking`, `downloading`, `extracting`, `ready` or `error`.

### UpdateInfo

```json
{
  "current_version": "1.4.0",
  "latest_version": "v1.5.0",
  "has_update": true,
  "release_name": "WEngine-Plus v1.5.0",
  "release_notes": "…",
  "download_url": "https://github.com/…/wengine-helper.exe",
  "status": "idle",
  "progress": 0.0,
  "error": null
}
```

`status` is `idle`, `checking`, `downloading`, `ready_to_install`, `installing` or `error`.

### WorkshopItem

| Field | Type | Notes |
|---|---|---|
| `workshopid` | string | Steam published-file id |
| `title`, `titleoverride` | string | `titleoverride` wins in the UI when set |
| `preview`, `previewsmall` | string | Preview image URLs |
| `tags` | string | Comma-separated Steam tag names |
| `type`, `typelabel` | string | `Scene`, `Video`, `Web`, `Application` |
| `status` | string | `downloadable` for workshop items |
| `file` | string | `workshop/<id>` |
| `author`, `authorsteamid`, `author_url`, `author_avatar` | string | Author fields, possibly empty |
| `description` | string | Details page only |
| `file_size`, `filesizelabel` | string | Human-readable size |
| `rating`, `ratingrounded`, `hasrating` | number/bool | Rating is 0–100; stars are 1–5 |
| `votesup` | integer | Upvotes |
| `is_collection`, `approved`, `portrait` | bool | Derived flags |
| `posted_date`, `updated_date` | string | Steam date strings |
| `rating_star_file`, `num_ratings` | string | Steam sprite file / rating count text |
| `installed_ts` | integer | Local install timestamp (metadata only) |

### WorkshopPage

```json
{
  "action": "queryWorkshop",
  "wallpapers": [ … ],
  "pagecount": 12,
  "token": 1,
  "isbackup": false,
  "total_items": 587
}
```

### TaskStatus (download)

```json
{
  "pubfileid": "123456789",
  "status": "Completed",
  "account": "Auto",
  "phase": "completed",
  "progress": 100.0
}
```

`phase` is `starting`, `running`, `completed`, `failed` or `cancelled`; `status` is the
human-readable line (the last DepotDownloaderMod output line, or a terminal label).

### ExtractStatus

```json
{ "pubfileid": "123456789", "status": "Extraction completed", "phase": "completed", "progress": 100.0 }
```

The same phase vocabulary as a download; `pubfileid` is the wallpaper id or the source path when no
id was supplied.

## Overlay bridge summary

The overlay wraps these routes. See `frontend/wengine-plus.js` for the exact signatures.

| Bridge method | Route |
|---|---|
| `ping`, `waitForPing`, `ensureRunning` | `GET /api/ping` |
| `startHeartbeat` | `POST /api/heartbeat` |
| `shutdown` | `POST /api/shutdown` |
| `getAuthStatus` | `GET /api/auth/status` |
| `loginWithCookie` | `POST /api/auth/cookie` |
| `loginSystemAccount` | `POST /api/steam/login/system` |
| `getAccounts`, `selectAccount`, `addAccount`, `removeAccount` | `/api/accounts/*` |
| `startAccountQr`, `pollAccountQr`, `cancelAccountQr` | `/api/accounts/qr/*` |
| `getPluginStatus`, `ensurePlugins` | `/api/plugins/*` |
| `getDotnetStatus`, `ensureDotnet` | `/api/dotnet/*` |
| `getAllMetadata`, `saveMetadata`, `deleteMetadata` | `/api/metadata/*` |
| `checkUpdate`, `getUpdateStatus`, `startUpdateDownload`, `applyUpdate` | `/api/update/*` |
| `browse` | `GET /api/workshop/browse` |
| `getItemDetails` | `GET /api/workshop/item` |
| `downloadItem`, `cancelDownload`, `getDownloadsAll` | `/api/workshop/download*` |
| `extractItem`, `getExtractStatus`, `pickFolder` | `/api/workshop/extract*`, `/api/dialog/folder` |
| `deleteWallpaper` | `POST /api/workshop/delete` |

`POST /api/auth/logout` is called directly by the overlay's logout handler, outside the bridge.
